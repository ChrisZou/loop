# Loop

原生 SwiftUI macOS 审阅工具：AI 用 `loop review` 把方案交给你，你在原文上选中文字逐条批注，点「提交」后反馈直接回到 AI，不用复制粘贴。

需要 macOS 14+、Xcode Command Line Tools（Swift 5.9+），无第三方依赖。

## 构建与安装

```sh
swift build -c release
./build-app.sh
ln -sf "$PWD/bin/loop" ~/.local/bin/loop   # 一次性安装，~/.local/bin 需在 PATH 中
```

`build-app.sh` 生成 `build/Loop.app`，Bundle ID 为 `com.chris.loop`，默认使用钥匙串里第一张 Developer ID Application 证书签名，可用 `LOOP_SIGNING_IDENTITY` 指定，找不到证书时退回 ad-hoc 签名。此构建未公证。

命令行工具和 `loop-review` skill 打包在 App 内。打开 App 时如果缺少它们，会先显示安装页：把 `loop` 软链到 `~/.local/bin/`，把 skill 软链到 Claude Code 的 `~/.claude/skills/`、Codex 的 `~/.agents/skills/`、WorkBuddy 的 `~/.workbuddy/skills/`（只装已存在的 Agent，都没有时装 Claude Code；已在 `~/.codex/skills/` 的算已安装）；登录 shell 的 PATH 里没有 `~/.local/bin` 时，再往 shell 配置（zsh 为 `~/.zshenv`）追加一行。`loop review` 发起的审阅窗口不经过安装页。

## 发起审阅

```sh
loop review 方案.md                      # 或：生成方案的命令 | loop review -
loop review --agent Codex 方案.md        # 记录来源 agent（也可用 LOOP_AGENT_NAME）
loop review --detach 方案.md             # 立刻返回 {"id":…}，适配有命令超时的 agent
loop wait <id> [--timeout 540]           # 等待 detach 会话；超时退出码 2，可续等
```

`loop review` 打开审阅窗口（标题是方案的第一个一级标题，没有就用文件名），然后阻塞等待：

- 点右上角「提交」或按 `⇧⌘↩`：反馈打印到标准输出，退出码 0。没有批注、总评，也没改过勾选时会先确认，提交内容为「我看过了这版方案，没有修改意见，可以按这版继续。」
- 没提交就关窗：标准错误输出「未提交」，退出码 1。批注暂存在 `~/Library/Application Support/Loop/reviews/`，再次审阅同一份方案会恢复，提交后删除。提交成功后会追加一条记录到 `~/Library/Application Support/Loop/history/`（含方案全文与反馈），冷启动首页可打开查看。网页端历史合并待接。

AI 代理在后台运行这条命令，命令结束就是用户提交了，读取输出即可拿到反馈。每次审阅是独立进程（`open -n`）。也可以直接运行 `Loop --review <文件> [--out <反馈文件>] [--agent <名称>]`，不传 `--out` 时反馈写到标准输出。不带参数打开 Loop（例如在 Finder 里双击）进入批注记录首页，可回看本机已提交的方案与反馈。

## 使用

- 界面风格是「红笔批改」：原文是灰色桌面上一张居中的白纸（最宽 760pt），只读；标题用衬线体（西文 New York、中文宋体），章节编号标朱红。Markdown 语法符号（`#`、`**`、反引号、`>`、代码围栏）隐藏，列表符号画成圆点，代码块画成卡片，行内代码带上下对称的圆角底色，引用带左侧竖线。GitHub 风格的表格（表头、`|---|` 分隔行、`:---:` 对齐）排成真正的表格：上下粗线、表头下细线、行间发丝线，没有竖线；列宽按内容分配，短表头和四五个字以内的短语不折行，窗口变宽变窄时重新分配。单元格里同样可以选字批注，跨单元格的引文用「 | 」隔开，复制出来的仍是原始 Markdown。图片 `![说明](路径)` 直接显示：相对路径按方案文件所在目录解析（路径里有空格可写成 `<图片/架构 图.png>`，`%20` 也认），也支持绝对路径、`~/`、http(s) 网络图片（后台加载）和 data URI；宽图缩到正文宽度、最高 560pt，按 Retina 截图的实际尺寸显示，独占一行的图片上下多留一点空白，找不到的图片显示成写着说明文字的浅灰占位块；双击图片用「预览」或浏览器打开原图；选中图片也能批注，引文里写成「[图片：说明]」。任务列表 `- [ ]` / `- [x]` 画成复选框，点一下切换勾选：方案里原本的勾是墨色，你改过的是朱红色，再点一下改回去；改过的项随提交一起回传为「待办的勾选状态改为：- [x] …」，方案文件本身不动，由 AI 在下一版里更新。这些都只改样式和字形，不改原文。跟随系统的浅色 / 深色外观。
- 批注是行内的：被批注的原文画上朱红下划线，最后一个字后面有一个朱红圈码，序号与提交顺序一致。鼠标悬停下划线文字或圈码弹出批注卡片（嵌套时显示最内层那条），点击圈码编辑或删除。同一处结尾的多条批注并排显示。卡片浮在正文上，打开时窗口保持激活状态。
- 选中文字后按 `⌘↩`，或点击工具栏「批注」/ 选区上方浮现的朱红「批注」按钮（选区贴着窗口顶部时出现在下方），在卡片里写意见，`⌘↩` 或「保存」确认，`Esc` 或「取消」放弃。卡片打开时点别处会自动保存已输入的内容。选区首尾的空白、换行和隐藏的 Markdown 符号会自动去掉，引文里也不带隐藏的符号。
- 「总评」可以写多条：在窗口底部的圆角输入框里写，回车换行，`⌘↩` 保存。保存的总评带编号列在输入框上方，输入框随即清空，可以接着写下一条。点某条总评可以在输入框里修改（`⌘↩` 保存，`Esc` 放弃），悬停可删除。输入框和列表都与白纸同宽。只有一条总评时导出为「总体意见：…」，多条时按编号列出。
- 批注和总评都可以附图：截图后在输入框里 `⌘V` 直接粘贴，或把图片文件、截图缩略图拖到批注卡片或总评框上，也可以点批注卡片左下角、总评框右侧的图片按钮选文件。图片以缩略图排在文字下面，点开用「预览」看大图，悬停点 × 移除；只有图片、没写字也能保存。剪贴板上有文字时 `⌘V` 照常粘贴文字。图片复制到 `~/Library/Application Support/Loop/attachments/<方案>/`（PNG、JPEG、GIF、WebP 原样保存，其他格式转成 PNG），提交时每张写成一行「附图：<本机路径>」，跟在对应的批注或总评后面，反馈开头注明附图要打开看。提交后图片保留，AI 才能打开；方案的草稿已删除且 30 天没有改动的图片文件夹，在下次审阅时清理掉。
- 右上角「提交」一次提交全部批注、勾选改动和总评（输入框里还没保存的文字会作为最后一条一起提交），「预览」可先看提交内容。标题居中，旁边显示批注数量和改过的勾选数。

批注按文档位置排序，使用与 NSTextView 一致的 UTF-16 范围。

## 演示与自检

```sh
LOOP_DEMO=1 .build/release/Loop
LOOP_DEMO=1 LOOP_DEMO_PREVIEW=1 .build/release/Loop
.build/release/Loop --selftest
```

演示模式审阅一份中文待办 App 方案，带 3 条批注和总体意见，不读写暂存；提交后反馈打印到标准输出。第二个命令在启动时自动打开提交预览。

`--selftest` 不启动界面、不读写暂存，使用临时目录，校验提交的完整格式、排序、多行引文和意见、选区修剪与引文去除 Markdown 符号、行内图标位置、悬停预览（离屏窗口里走真实的文字命中逻辑）、表格（单元格划分、对齐、同一行单元格横向并排、跨单元格引文、复制原文、代码块和无分隔行的竖线不算表格）、图片（替换成附件字符后下标不变、隐藏语法、`<>` 路径和标题、`%20` 路径、相对方案目录解析、缩到正文宽度、缺失图片、代码里不算、引文写成「[图片：说明]」）、任务列表（识别与隐藏前缀、点击复选框切换、导出格式、勾选随草稿保存、连续待办项的段间距）、输入法拼写中总评和批注输入框的占位文字让位（离屏渲染后读像素）、附图（导出格式、旧草稿兼容、粘贴截图 / TIFF / 图片文件、文字照常粘贴、非图片文件忽略、只有图片的批注和总评、在窗口里发真实 `⌘V` 键盘事件粘贴、拖进来的图片文件不会变成路径文字、卡片随图片变高、过期图片清理）、审阅参数解析、提交内容与反馈文件写入、演示数据和 JSON 往返；失败时返回非零退出码。

提交格式由纯函数 `FeedbackExporter.export(text:comments:generals:hidden:checks:)` 生成，位于 `Sources/Loop/FeedbackExporter.swift`。

## 发布（签名 zip / Homebrew）

在一台已导入 Developer ID 证书的 Mac 上：

```sh
./scripts/package-release.sh
# 可选公证：LOOP_NOTARY_PROFILE=你的notarytool钥匙串配置名 ./scripts/package-release.sh
```

产物在 `build/release/Loop-<版本>-macos.zip`（含 `Loop.app`，CLI 在 `Contents/Resources/loop`）。上传到 GitHub Release 后，更新 [`homebrew/loop.rb`](homebrew/loop.rb) 的 `version` / `sha256`，推到你的 Homebrew tap。

当前仓库内的 cask 是草稿：tap 名、是否公证、是否由 CI 发 Release，需你定。
