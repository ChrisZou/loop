# Loop

原生 SwiftUI macOS 审阅工具：AI 用 `loop review` 把方案交给你，你在原文上选中文字逐条批注，点「提交」后反馈直接回到 AI，不用复制粘贴。

需要 macOS 14+、Xcode Command Line Tools（Swift 5.9+），无第三方依赖。

## 构建与安装

```sh
swift build -c release
./build-app.sh
ln -sf "$PWD/bin/loop" ~/.local/bin/loop   # 一次性安装，~/.local/bin 需在 PATH 中
```

`build-app.sh` 生成 `build/Loop.app`，Bundle ID 为 `com.chris.loop`，使用团队 `W4SX57U6XB` 的 Developer ID Application 证书签名，找不到证书时退回 ad-hoc 签名。此构建未公证。

## 发起审阅

```sh
loop review 方案.md          # 或：生成方案的命令 | loop review -
```

`loop review` 打开审阅窗口（标题是方案的第一个一级标题，没有就用文件名），然后阻塞等待：

- 点右上角「提交」或按 `⇧⌘↩`：反馈打印到标准输出，退出码 0。没有批注也没有总评时会先确认，提交内容为「我看过了这版方案，没有修改意见，可以按这版继续。」
- 没提交就关窗：标准错误输出「未提交」，退出码 1。批注暂存在 `~/Library/Application Support/Loop/reviews/`，再次审阅同一份方案会恢复，提交后删除。

AI 代理在后台运行这条命令，命令结束就是用户提交了，读取输出即可拿到反馈。每次审阅是独立进程（`open -n`）。也可以直接运行 `Loop --review <文件> [--out <反馈文件>]`，不传 `--out` 时反馈写到标准输出。不带参数打开 Loop（例如在 Finder 里双击）只会提示用法，退出码 64。

## 使用

- 界面风格是「红笔批改」：原文是灰色桌面上一张居中的白纸（最宽 760pt），只读；标题用衬线体（西文 New York、中文宋体），章节编号标朱红。Markdown 语法符号（`#`、`**`、反引号、`>`、代码围栏）隐藏，列表符号画成圆点，代码块画成卡片，引用带左侧竖线。这些都只改样式和字形，不改原文。跟随系统的浅色 / 深色外观。
- 批注是行内的：被批注的原文画上朱红下划线，最后一个字后面有一个朱红圈码，序号与提交顺序一致。鼠标悬停下划线文字或圈码弹出批注卡片（嵌套时显示最内层那条），点击圈码编辑或删除。同一处结尾的多条批注并排显示。卡片浮在正文上，打开时窗口保持激活状态。
- 选中文字后按 `⌘↩`，或点击工具栏「批注」/ 选区上方浮现的朱红「批注」按钮（选区贴着窗口顶部时出现在下方），在卡片里写意见，`⌘↩` 或「保存」确认，`Esc` 或「取消」放弃。卡片打开时点别处会自动保存已输入的内容。选区首尾的空白、换行和隐藏的 Markdown 符号会自动去掉，引文里也不带隐藏的符号。
- 「总评」在窗口底部的圆角栏里写，宽度与白纸一致。回车换行，`⌘↩` 保存，`Esc` 放弃这次修改；点别处也会自动保存。保存后显示「✓ 已保存」，点一下可再改。
- 右上角「提交」一次提交全部批注和总评（还在编辑的总评会先保存），「预览」可先看提交内容。标题居中，旁边显示批注数量。

批注按文档位置排序，使用与 NSTextView 一致的 UTF-16 范围。

## 演示与自检

```sh
LOOP_DEMO=1 .build/release/Loop
LOOP_DEMO=1 LOOP_DEMO_PREVIEW=1 .build/release/Loop
.build/release/Loop --selftest
```

演示模式审阅一份中文待办 App 方案，带 3 条批注和总体意见，不读写暂存；提交后反馈打印到标准输出。第二个命令在启动时自动打开提交预览。

`--selftest` 不启动界面、不读写暂存，使用临时目录，校验提交的完整格式、排序、多行引文和意见、选区修剪与引文去除 Markdown 符号、行内图标位置、悬停预览（离屏窗口里走真实的文字命中逻辑）、审阅参数解析、提交内容与反馈文件写入、演示数据和 JSON 往返；失败时返回非零退出码。

提交格式由纯函数 `FeedbackExporter.export(text:comments:general:hidden:)` 生成，位于 `Sources/Loop/FeedbackExporter.swift`。
